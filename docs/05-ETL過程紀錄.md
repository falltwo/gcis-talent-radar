## 0. 起點：原專案的資料問題

先讀了原專案（教授 repo）的 ETL 與引擎，確認下列問題：

| 檔案 | 問題 |
|---|---|
| `etl/extract_gcis_batch.py` | 公司名單來自 104 職缺；統編用 `hash(公司名稱)` 合成；資本額、門牌、是否增資用 `random.choice` 產生。產業動態表 `industry_dynamics_mart` 完全是依寫死參數加常態雜訊模擬出來的，沒有讀任何真實登記資料 |
| `etl/extract_demographics.py` | 18 歲人口、新生數直接寫死在程式裡 |
| `etl/extract_moe_udb.py` | 新生數用「在學人數 ÷ 4」估；註冊率缺值補 92.5 |
| `engine/*` | 預測只是 Z-score 加線性外推，沒有回測 |

結論：UDB 原始 CSV 是真的，其餘產業端資料都要重做。原則定為：**只用官方開放資料、不補值、不模擬、每個數字都能追到下載的那份檔案**。

## 1. 找資料

1. 從 data.gov.tw 下載**完整資料集目錄**（`https://data.gov.tw/datasets/export/json`，52,442 筆），用關鍵字（職缺、缺工、求才、勞保、工業區、工廠、臺中…）篩出約 900 筆候選。這比逐一搜尋可靠。
2. 對約 40 個候選資料集**逐一實際下載**，看欄位、期間、能不能切到臺中和製造業，排除只有網頁的、壞掉的、停更的。結果寫在 [DATA_CATALOG.md](DATA_CATALOG.md)。
3. 組員的〈03-資料集審查〉補上三個我們沒有的來源：GCIS 縣市 × 行業統計、EE520 工廠校正查詢、就業通查詢參數。逐項驗證後併入。

排除的（原因都是實測結果）：

| 資料集 | 原因 |
|---|---|
| 臺中市就業服務按職業／教育／年齡分（87870 等） | 18 個下載連結全部回 `500 Type error` |
| 臺中市工廠登記家數異動（103091） | 只到 2017-12 |
| 園管局潭子園區區內事業名錄（22304） | 匯出被截斷，而且沒有臺中資料 |

| 內政部出生數 | 只從 104 年起，涵蓋不到三年後的畢業生 → 改用高職各年級在學人數 |
| 104 人力銀行 | 民間網站，條款禁止爬取 |

## 2. 環境

- 系統 Python 3.12。只有 PyPI 的檔案伺服器（files.pythonhosted.org）很慢，約 0.01–0.2 MB/s；其他網站都有 8–11 MB/s。實測發現同一個 CDN 只有部分節點慢。大型 wheel（scipy、playwright、patchright）改用 `curl -C -` 續傳下載後再本機安裝；torch 改從 download.pytorch.org 安裝。**沒有修改 hosts 等系統設定。**
- Scrapling 0.4.15 的一般 Fetcher 仍會 import playwright／patchright，所以兩者都要裝（只裝 Python 套件，不下載瀏覽器）。
- 爬蟲只用一般 Fetcher，不用 StealthyFetcher 等繞過防爬的模式；先看過 robots.txt，請求之間至少間隔 0.3–2 秒。

## 3. 各來源的處理過程

### 3.1 GCIS 縣市 × 行業大類（新設／解散／現有）→ `tc_company_by_industry_monthly`

- 組員已經抓好新設的 171 個月檔，直接沿用；解散（795C3F99）、現有家數（ACA82CEE）用同一套解析。三個資料集格式相同，資本額單位都是新台幣百萬元（資料集頁面寫明）。
- **遇到的問題**
  - 2025-08、09 在三個統計資料集裡**都沒有**，設立清冊也沒有，確認是來源本身缺 → 補一列 NaN，標 `missing_at_source`，不補 0。
  - 2010-12、2011-12 是孤立的年底月份，全行業總計只有 130、299 家，2012 年月平均是 455 家 → 標 `isolated_before_series`，建模時排除。
  - 「現有家數」2014-11 的原始檔，縣市名稱在來源端就已經是亂碼（替換字元 U+FFFD），不是我們解碼錯誤 → 當作來源損毀處理，**不用列序去猜哪一列是臺中市**。
  - 「公共行政及國防；強制性社會安全」在 2024-12 改名，拆成兩條序列 → 統一去掉全形分號與空白。
- **異常值**：用前後各 6 個月的中位數加 MAD 標準化，|z| > 4 標 `outlier_candidate`，只標記不刪。製造業被標記的是：新設 2022-03（233 家）、解散 2019-05／06。
- **驗證**：長表跟 171 個原始月檔逐月比對，0 筆不一致；2026-08 製造業新設 75 家，與組員文件相同。

### 3.2 臺中市就業市場分析季報 → `tc_jobmarket_*`

- 勞工局「統計分析及通報」頁面一次列出全部季報，用 Scrapling 抓列表、下載 26 份 PDF（109Q1～115Q2）。
- 用 pdfplumber 抽表格。**新舊版面不同，修了三次：**
  1. 109Q4：月份欄「10、11、12」被折成兩行，只抽到「1」→ 改成依列序決定是季內第幾個月，並核對標籤開頭。
  2. 114Q4：百分比寫成「77.55 %」，中間有空格 → 先去掉所有空白。
  3. 109–110 年職業別表：名稱在第 2 欄；名稱折行時數字會重複出現；109Q1 的「求供倍數」欄還錯列到別的職業 → 用兩道檢核挑正確欄位：先比「求供倍數 ＝ 新登記求才 ÷ 新登記求職」，不符再比「求職就業率 ＝ 推介就業 ÷ 求職」。通過第二道的要重算倍數，並標 `rate_ratio_recomputed`（只有 109Q1 的機械設備操作、基層技術工兩列）。
- 表 4 職業別是**季合計**，另存一張表，不攤到月。
- 111 年市府接手勞動部委辦的臺中就業中心，範圍改變 → 加 `scope_period` 欄。
- **驗證**：每季三個月加總都等於季合計；113Q2 表 1 跟組員轉錄的 3 列逐格相同；月資料 2020-01～2026-06 共 78 個月，沒有缺月；職業別 26 季 × 9 類齊全。

### 3.3 經濟部 EE520 工廠校正統計 → `tc_factory_district_industry_annual`

- 查詢頁 `InvestigateG.aspx` 是 ASP.NET 表單。用 curl 取頁時，地區樹只有一個收合的節點；**改用 Scrapling 取頁，伺服器會回完整版（629 KB），406 個地區節點都內嵌在 HTML 裡**，不必模擬展開。
- 先重現組員提供的三筆，**完全相同**：大雅區 × 機械設備業，111 年 207 家／5,771 人、112 年 211 家／5,646 人、113 年 219 家／5,644 人。
- 每區送一次查詢（全部 26 個中類 × 兩個項目 × 86～113 年），29 區、每次間隔 2 秒。
- **遇到的問題**
  - 兩字區名中間是全形空白（「中　區」）→ 比對前去掉所有空白；只在「台中市」之下的 29 個節點裡找，避免抓到其他縣市的「東區」「北區」。
  - 結果頁的項目名稱帶單位（「營運中工廠家數 (家)」）→ 去掉括號。
  - 「化學材料及肥料業」的「料」在原站是相容字元 U+F9BE，外觀一樣但比對不到 → 做 Unicode NFKC 正規化。
  - 結果頁沒有行業代碼 → 依行業統計分類第 11 次修正寫成對照表，對不到就報錯，不會默默留空。
- 未滿 4 家的格子原站顯示「*」→ NaN，標 `suppressed_lt4`；「-」標 `no_value`。工商普查年（85、90、95、100、105、110）原站沒有資料。
- **交叉核對**：113 年各區工廠家數加總，與臺中市政府的全市工廠校正調查**一致**（差 0 家）；員工數少 1.63%，就是保密格造成的。小產業影響大，例如產業用機械設備維修及安裝業少了 82%。

### 3.4 勞保 → `tc_labor_insurance_annual`

- 資料集 100999 每年只公開 12 月一期（107–114 年），粒度是縣市 × 單位類別 × 業別 × 就保註記，用代碼表轉成中文。
- **口徑**：臺中製造業 2025-12，產業勞工 361,509 人、公司行號員工 14,460 人、職業勞工 35,065 人、其他 24 人。依勞保條例，前兩類和其他事業員工都是受僱者，合計 **375,993 人**；職業勞工是工會加保、無一定雇主，不算。組員文件只取產業勞工，會少算約 4%，所以加了 `employee_scope` 欄讓口徑寫在表上。
- 臺中製造業受僱者 2018 年 412,274 人，2025 年 375,993 人，少了約 9%。

### 3.5 臺中市開放資料 → `tc_factory_count_district_monthly`、`tc_factory_survey_city_annual`

- 兩個資料集都是同一種長表 JSON（地區、項目、欄位名稱、數值、日期），另外附機關聯絡電話與 Email，不保留。
- 工廠家數月快照只有 18 期，而且不連續（2024-08～2026-07），只做現況描述。
- 工廠校正調查是**全市**資料：原檔的「行政區域代碼」是發布機關的所在地，不是分區。這個欄位先前曾被誤讀成分區資料，這次確認後在表的註記寫明。

### 3.6 教育 → `tc_vocational_dept_annual`、`tc_udb_dept_annual`

- 高中職科別資料（base2.csv，103～114 學年）只取臺中市，排除附設國中部。各年級在學人數就是未來三年的畢業生管線，這是**取代出生數推估**的實測值。
- 大專 UDB 沿用原 repo 已下載的原始檔（下載日期沒有紀錄）。原 config 其實沒有定義臺中校清單，所以依 UDB 實際校名整理出位於臺中的 17 所，排除在桃園的國立體育大學。**不做「在學 ÷ 4」或補註冊率。**

### 3.7 台灣就業通 → `tc_taiwanjobs_snapshot`

- 採用組員實測的參數 `city=13&zipno=…&count=1000&T=CSV`，對 29 個郵遞區號各查一次。最多的西屯區 379 筆，離 1,000 筆上限還很遠；程式保留上限警告。
- 工作內容全文可能有聯絡人、電話 → **原始檔落地前就刪掉這一欄**（第一版只在整理後的表刪，推送前檢查時發現原始檔還在，已修正）。
- 跨區重複的職缺以（快照日, 職缺網址）去重；工作地點寫「台中市不限」或與查詢區不符的，用 `location_flag` 標記。
- 第一份快照：2026-10-05，2,856 筆。就業通沒有歷史資料，**要每天跑才會累積**。

### 3.8 行政區 × 中類的公司事件 → `tc_mfg_company_events_monthly`（方法待決）

- 設立、解散、變更清冊各 161 個月（2013-02～2026-08，缺 2025-08、09）。下載當下只留臺中市的列、刪除代表人；manifest 記錄的是原檔雜湊。
- 臺中事件：設立 96,447、解散 39,941、變更 339,459 筆。
- 產業別：先用財政部稅籍（BGMOPEN1，171 萬筆，只留統編與行業代號）對統編，取「主要行業代號」前 2 碼當中類。
- **試過但不可行**：GCIS API 的 `in (...)` 和 `or` 都無法一次查多家，只能逐家查。需要補查的有 52,790 家（解散公司 99.9% 不在稅籍裡）。
- **發現定義問題**：最近一年的判定率已經 95%，但算出來的製造業新設家數只有官方統計的 20–30%。拿 2026-08 的 504 家用 API 查營業項目：
  - 稅籍主要行業是製造：約 20 家
  - 第一順位營業項目是製造：45 家
  - 任何一項營業項目是製造：102 家
  - 官方統計：75 家
  
  官方的分類規則用公開資料重現不出來。
- **目前的處理**：表裡只放新設與增資（稅籍定義），解散事件在判定率低於 80% 的月份不列入，避免看起來像「沒有退場」，並在註記寫明定義差異。**要用哪個定義，等團隊決定。**

## 4. 通用處理與檢查

- `etl/sources/common.py`
  - 每個原始檔都記到 `data/raw/_manifest.csv`：網址、時間、大小、SHA-256。
  - 個資欄位用規則（代表人、負責人、聯絡人、電話、Email…）刪除，`write_processed` 寫出前會再檢查一次。
  - GCIS 憑證缺 Subject Key Identifier，只關掉 Python 的 strict 檢查，仍然驗證憑證。
- `etl/quality.py` 產生 `reports/DATA_QUALITY.md`：個資欄位、主鍵重複、缺值、各表專屬檢查（缺月、EE520 對全市、勞保口徑、事件判定率）。
- `tests/test_real_etl.py`：把人工對過原始來源的數字寫成測試，例如大雅機械三筆、113Q2 表 1、109Q4 折行月份、勞保 361,509／375,993、GCIS 缺月要保持 NaN。目前 27 項全過（含預測引擎測試）。
