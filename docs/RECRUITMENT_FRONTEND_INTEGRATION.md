# PR31 與 PR22 招募填表流程

目前流程：側邊對話提出需求 → AI套用職位範本及擬定建議 → 右側觀看實際瀏覽器填表 → 同頁人工檢查與修改 → 確認送審 → 待審核。

不顯示填表前的條件表單、帳密或草稿功能。對話框下方固定快捷按鈕；薪資快捷鍵先帶入可編輯問題。連按兩次Enter（700毫秒內）送出，單次Enter及Shift+Enter換行，中文組字不誤送。

## 同頁實況及人工修改

Computer Use在背景Chrome用截圖與滑鼠鍵盤操作，畫面與實際點擊位置回傳右側工作台，不彈出其他Chrome視窗。這是受控瀏覽器實況，不是整個Windows桌面的串流。

第一次在求才網站儲存後，停止AI填寫。完全一致回報FILLED，有差異回報REVIEW_REQUIRED並提供mismatches、actual_job及job_id；兩者都交給人工檢查，不交回AI修正。多職位依序填寫後，在同一工作台逐筆檢查。

右側直接內嵌本次職缺的原網站編輯模式 `/mock104?review_job=...`，可手動修改所有欄位。每筆按「儲存並確認此職缺」後，工作台從後端重新讀取實際內容與revision。有未儲存修改時禁止切換職缺與送審。

全部確認後主按鈕「確認送審」只呼叫submit，停在PENDING_APPROVAL，不自動approve或complete。送審前核對全部內容及版本，後端再次驗證expected_revision；版本變更拒絕送審。重試略過已送審項目。側邊對話可查送審與刊登紀錄。

實際目標是本機模擬求才網站，不會送到104或其他外部平台。來源、執行、停止與人工修改均使用同源工作階段。

## 職位範本及台灣薪資

`POST /api/recruitment/mvp/execution/prepare` 優先套用既有職位條件範本，缺少時由AI建議。人數、職責及薪資以使用者明確指定條件為優先。未指定金額先面議；班制與工時等建議在填寫依據說明。

薪資使用勞動部台灣就業通資料集44062的官方CSV接口。僅比對職稱、實際地區、有效期限與完整月薪上下限，按職缺網址去重。顯示開價上下限各自中位數、樣本數、資料日期與讀取模式，不冒稱平均實領薪資、不覆寫企業指定金額。

當地少於3筆時依序比對鄰近區、臺中市及主要就業市場，明示實際參考地區。接口快取15分鐘；失敗可讀既有快照，保留舊日期與非即時標示。全部不足時對話會繼續查詢附來源的台灣薪資調查。O*NET只用於職責技能，不作台灣薪資來源。

同時問薪資、工作內容或技能時逐項回答，不因薪資查詢成功而提前結束；分流器漏掉的面向會從原問題補回。

## 主要接口

- 對話：`POST /api/recruitment/mvp/assistant`
- 薪資參考：`GET /api/recruitment/mvp/salary-reference`
- 執行：`POST /api/mock104/agent/approve`、`agent/browser/start`
- 實況：`GET /api/mock104/agent/run`
- 停止：`POST /api/mock104/agent/cancel`
- 人工保存：`PUT /api/mock104/jobs/{job_id}`
- 確認送審：`POST /api/mock104/jobs/{job_id}/submit`，包含expected_revision

## 三欄招募工作台與城市薪資範圍

寬螢幕採左側「招募助理與需求」、中央「Agent即時操作／人工檢查」、右側「送審與刊登紀錄」三欄。左側完整呈現回覆與來源，不自動彈出完整閱讀對話框；新回答定位到開頭，可放大對話，輸入與快捷列保留在底部。中小螢幕依序改成兩欄或直向排列。

臺中薪資查詢不受地圖選點的行政區限制，直接從臺中市整體資料開始；不足時再參考新竹市與附來源的其他城市調查。參考地區仍明示，不能把其他城市資料稱作臺中行情。
