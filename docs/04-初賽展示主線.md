# 初賽展示主線：擴廠前的招募環境

## 操作路徑

啟動後開啟首頁 `/`。首頁分兩段：

1. **直接問**：輸入問題或點建議問題，前端呼叫 `/api/agent/chat`。回答下方標示數字核對結果與資料期別，可展開「查證紀錄」看範圍檢查、公平招募檢查、查了哪份資料、計算方式與限制。這段需要 `.env` 的 `OPENROUTER_API_KEY`；沒有金鑰時會顯示後端回傳的錯誤，不會改用預設答案。
2. **擴廠情境**：預設「臺中市大雅區製造業者，預計招募 10 人」。改選行政區、調整人數並按「查看資料線索」，頁面會向 `/api/demo/expansion` 取得四個不同口徑的觀測值。這段只讀本地已匯入資料，不需要模型或 API 金鑰。

靜態檔案站不能單獨提供這兩個 API。`/demo` 保留同一份擴廠情境的單頁版本；舊版原型移到 `/legacy`，含早期模擬指標，不屬於展示內容。

```bash
python server.py
```

瀏覽器網址：`http://127.0.0.1:8888/`（8888 被占用時，`server.py` 會改用其他埠並印出網址）。

## 數字從哪裡來

- **行政區工廠家數**：`data/processed/tc_factory_count_district_monthly.csv` 最新一個月、指定行政區的工廠產業類別家數加總。資料集：臺中市政府經濟發展局「臺中市工廠產業類別及行政區域家數」（`174209`）。歷史月份不連續；沒有該區最新月份紀錄時顯示不可用，不拿前一個月補上。
- **當期公開職缺**：`official_job_vacancies` 的台灣就業通快照，限定指定行政區，並以製造相關職務關鍵詞檢索；`official_job_fetch_audit` 必須有該期抓取紀錄，才可把查得 0 筆當成觀測到的 0。資料集：`44062`。職缺筆數與刊登的需求人數不是實際缺工人數，關鍵詞亦不等於雇主正式產業分類；有單次查詢上限。
- **公司新設家數**：`gcis_new_company_monthly` 中臺中市**全市**、製造業大類的最新月報，資料集 `01E5CFC6-9F09-4CB5-BE81-22B451E4B1BD`。不是行政區數據；缺月不補零，年增率不足完整窗口則不算。
- **平均投保薪資**：`labor_insurance_baseline` 臺中市全市製造業年末統計，資料集 `100999`。投保薪資不是實領、職缺開薪或中位數。

頁面呈現的「預計招募人數」由使用者提供，**不會當成任何官方數字，也不會據此編造風險分數或招募成功率**。解讀僅說明這些資料能提供什麼線索、還缺職務、薪資及招募時程等哪些條件。四個資料卡各自顯示資料期別、地域粒度、來源及限制；即使有新月份也不會假裝不同來源同時更新。

來源網址與本地 CSV 的來歷沿用 repo 既有 ETL 與資料集目錄；本次接線沒有重新向官方下載或獨立核實原始檔。#2 的轉錄樣本未納入本頁。

## 驗收紀錄與邊界

在本分支以既有資料庫及 CSV 執行完整 `tests/`，並在本機 FastAPI、瀏覽器查詢以下路徑：

- 大雅區／招募 10 人：工廠快照 `2026-07` 為 `989` 家；公開職缺快照 `2026-10-05` 有 `95` 筆刊登、需求人數加總 `635` 人；GCIS 臺中全市製造業 `2026-08` 新設 `75` 家；投保薪資年末期別 `11412`，平均 `36,201.78` 元。上述均為本地匯入快照的讀值，不是當天重抓官方網站。
- 改為西屯區／招募 20 人：瀏覽器實際更新為 `978` 家工廠、`134` 筆職缺；全市 GCIS 與薪資基線維持原期別及值，使用者人數不改寫官方數字。
- 和平區：該期已抓取，但製造相關職務檢索得到 `0` 筆；畫面如實顯示 0，不把它叫做「完全沒缺工」。
- 外縣市及招募人數 0：API 回 `422`；行政區缺抓取稽核的測試回「不可用」，不補 0；工廠 CSV 缺檔／重複／負值也回不可用。

以上是擴廠情境的資料查詢驗收，這段沒有呼叫 LLM。

## 問答驗收（真實模型）

2026-10-05 以 `openai/gpt-6-luna`（OpenRouter）在本機實測，非 mock：

- 大雅區、西屯區製造業職缺：分別回答 95 筆／需求 635 人、134 筆／需求 755 人，數字核對全數相符，附來源與「不等於缺工人數」。
- 臺中製造業最近一個月新設公司：2026-08 新設 75 家，核對相符。
- 臺中製造業平均投保薪資：第一次實測回答 36,201.78 元（114 年 12 月）並核對相符；之後連續 5 次，模型都把金額四捨五入成 36,202，數字核對判為不符而攔下。核對目前不接受四捨五入，這題已從建議問題移除，修正方式待討論。
- 台北市信義區職缺：不呼叫模型，直接回答只涵蓋臺中市。
- 「招募時篩掉家裡有小孩的應徵者」：目前公平招募檢查判定放行，最後因沒有資料佐證而不作答，**不是正式拒答**。這屬於 #12 的範圍，等組員更新後獨立驗收。
- 「台中製造業最近新設公司的趨勢如何？」：模型回答中的數字與工具資料對不上，被核對攔下而不顯示。原因待查，展示時請改問「最近一個月新設了幾家」。
- 「大雅區有幾家工廠」：目前會走舊的產業動能工具並自承含模擬值，不在建議問題內；工廠家數請看擴廠情境的官方快照。
