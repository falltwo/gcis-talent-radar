本輪只新增規格，不修改正式產品。

## A 一份報告，串起三項設計
```callout info 產品目標
企業比較2–3區的招募環境。
GCIS改變摘要、比較資格與查證行動。
AI只能選用後端核准的主張。
```

```flow LR
企業情境 -> 固定資料快照
固定資料快照 -> 事實帳本: FactLedger
事實帳本 -> 比較與GCIS規則
比較與GCIS規則 -> 核准主張: ClaimCatalog
核准主張 -> 統一呈現: 頁面、AI與匯出
```

模型不可用時，規則摘要、資料來源與列印仍可用。
核驗代表與本次核准來源及規則一致。
它不證明來源無誤，也不證明缺工因果。

## B 企業輸入，如何真正影響輸出
| 輸入 | 第一版規則 | 改變的結果 |
|---|---|---|
| 行政區 | 2–3區、不重複 | 比較欄與各區資料 |
| 製造業中類 | 單選、使用catalog版本 | 公司事件與可對應工廠資料 |
| 職類 | 單一職務檢索條件 | 公開刊登與相關摘要 |
| 觀測月份 | 最新或固定歷史月 | 資料期別與缺資料狀態 |
| 招募起迄月份 | 最多12個月 | 每月到職目標 |
| 淨新增人數 | 使用者確認的正整數 | 企業規劃，不改官方數字 |

觀測月份與企業招募月份分開。
未來招募時間不會產生未來官方職缺。

### 規劃範例

31人、3個月，可分成11／10／10人。
改成60人，月目標變成20／20／20人。
官方職缺、公司事件及薪資保持原值。
上述是規劃示例，不代表預測可招到。

### 操作流程

選條件 → 確認各來源期別 → 建立報告。
再看摘要、比較表、證據與月計畫。
最後可追問、列印或下載JSON。

正式入口使用`/compare`與`/reports/{id}`。
沿用既有比較服務，移出legacy流程。

## C 報告畫面與資料資格
報告先回答能觀察到什麼，再列未知與下一步。

| 區塊 | 內容 | 邊界 |
|---|---|---|
| 摘要 | 最多三項核准主張 | 不產生招募成功率 |
| 公開職缺比較 | 筆數、需求人數、不同公司名稱數 | 同日、同條件、同規則 |
| GCIS同業訊號 | 全市背景、區域已分類樣本 | 兩種母體分開 |
| 共同背景 | 全市薪資、趨勢與可用預測 | 不複製成各區數字 |
| 證據抽屜 | 來源、期別、欄位、公式與版本 | 每個數字可查 |
| 企業計畫 | 月目標與待確認條件 | 使用者規劃 |
| 下一步 | 規則觸發的查證事項 | 不替企業選唯一地點 |

### 三個重要狀態

- 完整抓取的0筆：本快照無符合刊登。
- 達查詢上限：顯示至少N筆，取消排名。
- 未取得或缺分類：顯示未知，不補0。

同一資料組跨區必須一致。
不同資料組可以不同月份，各自標期別。
歷史月沒有職缺快照，就明示未留存。

### 保存與匯出

報告固定來源快照、Facts、Claims及限制。
ETL更新只影響新報告。
原頁、AI與列印持續使用原版本。
修改條件會建立新報告。

## D GCIS如何真正改變結論
### 先分開兩條證據

| 證據 | 允許用途 | 不允許用途 |
|---|---|---|
| 官方全市製造業統計 | 完整窗口的數量與方向 | 下推某區或某職類 |
| 區域中類已分類事件 | 樣本觀察與查證線索 | 當區域母體、算缺工排名 |

分類率達80%或100%，也不自動成為完整母體。
當前稅籍回填歷史，仍保留標籤時點限制。
解散資料不足時，不產生淨增或退出率。

### 規則直接控制摘要與行動

| 規則 | 條件 | 產品變化 |
|---|---|---|
| GS01／02 | 全市完整12月比前12月增減 | 顯示全市方向與查證理由 |
| GS03 | 本區有有效已分類活動 | 增加查證相關職類招聘的工作 |
| GS04 | 分類／歷史標籤有限制 | 先顯示限制，取消區域勝負 |
| GS05 | 已分類樣本無命中 | 說未觀察到，不說無競爭 |
| GS06／07 | 淨增資格不足或來源缺失 | 阻擋比較，列補資料工作 |

同公司三次變更，不算三家企業。
首次資本變更沒有前值，就屬未知。
公司登記地址也不等於工作地點。

### 有／無GCIS的對照

固定職缺、薪資與企業計畫，只改GCIS。
摘要、證據缺口與下一步應依規則改變。
其他來源數值必須完全相同。
這是機制驗收，尚不是預測效益證明。

## E AI不再自行寫核心事實
```sequence num
後端 -> 官方工具: 固定情境與快照
官方工具 -> 後端: 結構化結果與證據
後端 -> 主張清單: 依規則建立可說的內容
主張清單 -> AI: 核准ID與固定標題
AI -> 驗證器: 只回選擇與排序
驗證器 -> 呈現器: 合法主張與必要限制
呈現器 -> 使用者: 同版本的文字、數值及引用
```

### 每個Fact都鎖定意義

| 綁定 | 避免的錯誤 |
|---|---|
| 指標與單位 | 200人被寫成200筆 |
| 地區與主體 | 西屯值套到大雅 |
| 期別與資料性質 | 觀測冒充預測 |
| 篩選與版本 | AND與OR混用 |
| 母體與品質 | 樣本冒充完整市場 |
| report與manifest | 跨報告或混版引用 |

### 模型輸出限制

只允許`report_id、catalog_hash、sections`。
sections只能含`heading_id、claim_ids`。
模型不能提交數值、單位、來源或自由段落。
標題也用白名單，避免偷加高風險判斷。

後端強制補上必要限制與證據缺口。
最多重試一次，不降低核驗規則。
仍失敗時，使用後端標準主張順序。
未驗證的模型token不先串流給使用者。

## F API、資料與工程邊界
| API | 工作 |
|---|---|
| GET comparison-options | 取得有效條件、月份與規則版 |
| POST reports/expansion-comparison/resolve | 固定預覽期別，回傳解析權杖 |
| POST reports/expansion-comparison | 建立固定版本報告 |
| GET reports/{id} | 讀取原報告 |
| POST reports/{id}/questions | 針對原報告追問 |
| GET reports/{id}/export | 列印HTML或下載JSON |

### 重用與新增

- 重用既有行政區比較聚合與稽核。
- 新增固定快照參數，不複製另一套SQL。
- GCIS影子事件保留分類、重複與衝突。
- 用SQLite與不可變JSON保存報告即可。
- 每次請求共用request_id，各事件另有event_id。
- 報告與建置稽核在同一交易提交。

### 錯誤行為

輸入錯誤回422。
資料不足可建立有限報告。
必要保存或稽核失敗回503。
模型失敗不影響官方比較與列印。
公開部署時，報告ID仍需搭配存取權。

## G 工作包與開發順序
以下為建議估時，假設三條工作可並行。

| 包 | 主責 | 交付 |
|---|---|---|
| P1 | 後端 | 契約、固定快照、報告保存 |
| P2 | 資料 | GCIS影子資料、用途資格、規則 |
| P3 | 後端 | Fact、Claim、Renderer |
| P4 | 前端 | 正式比較頁、證據、計畫、匯出 |
| P5 | 後端＋前端 | 受限AI、fallback、稽核 |
| P6 | 全體 | 整合、反例、故障、企業任務 |

```timeline
10/27 | 定契約與情境 | 選中類、職類及工作分配
10/28–29 | 三線並行 | 固定快照、GCIS、前端fixture
10/30–31 | 正式資料接通 | 報告、證據、規劃及匯出
11/01–02 | AI與企業試用 | 核准主張、真模型、任務驗收
11/03–04 | 文件與凍結 | 同版部署、備援與測試紀錄
11/05–06 | 現場彩排 | 陌生問題、斷網、逾時
```

若工期落後，先延後人才管線與預測圖選配。
保留比較報告、GCIS規則與事實綁定。
不以省略未知或核驗來壓縮交付。

## H 驗收與完整規格
```callout info 三項完成標準
企業能完成比較、查證、規劃與匯出。
GCIS改變摘要、比較資格或下一步。
錯區、錯單位及無證據結論不能通過。
```

### 必測案例

- 31人改60人，只改月目標。
- 中類與職類分開篩選，不冒充雇主分類。
- 查詢截斷取消排名，缺資料不補0。
- GCIS分類跨80%，仍不升格母體。
- 西屯改大雅、200人改200筆都被擋。
- 真來源ID不能替假敘述洗白。
- 原報告在資料更新後保持一致。
- 模型故障仍有規則報告與匯出。

完整文件有42項具體驗收場景。
它們包含正常任務、反例及故障。
測試通過不代表通用零幻覺。
